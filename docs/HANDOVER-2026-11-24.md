## Added by Richard, 24 November 02:18: renders run without AI

When a video mission's scene is ready, the AI must not sit in the mission paying tokens while frames render
(23-24 November: 3D renders take about 5 s a frame on the CPU, and the AI kept polling, timing out and retrying).
- A `start_render` tool for studio missions: render command (OpenMontage VideoCompose, HyperFrames render_existing,
  `npx remotion render`, `npx hyperframes render`), working folder, output path. The sandbox server starts it in
  the background with no command timeout, logs to a file in the project, returns a job ID at once.
- The mission saves a checkpoint and pauses (existing checkpoint and continuation code): no model calls while it
  renders.
- A plain Celery job (no AI) checks the render every 30 seconds.
- When it ends the mission resumes with the facts: exit code, output path, ffprobe size and length, freezedetect
  result, last 50 log lines. The AI looks only on failure or to check the finished video.
- One render at a time on the machine; others queue (two CPU renders at once crashed the sandbox before).
- Tests: a short ffmpeg render completes with no model calls during it; a failing render resumes the mission with
  its error; the card shows "Rendering (no AI cost)" with the elapsed time.

Also from 24 November: the 3D runner remake (missions c79181f1, 2ed3f85c) worked through HyperFrames + Three.js +
CMU BVH mocap (BVHLoader) in atelier style. JAI's video instructions should name that route for 3D work too.
